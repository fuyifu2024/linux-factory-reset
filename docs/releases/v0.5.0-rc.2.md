# Linux Factory Reset v0.5.0-rc.2

## 中文

本次集中改进准备前检查与准备阶段的可见进度：

- `check [--storage /mnt/recovery]` 汇总独立检查结果，分为通过、阻碍、无法确认和未检查；检查一项失败后仍继续收集其他结果。包含发行版、根/启动分区、完整引导布局、必需工具、待恢复标记、Secure Boot、UEFI 变量访问、系统/启动盘工作空间和恢复盘空间估算。
- Secure Boot 信息缺失、不可读或异常不按“已关闭”处理；UEFI 检查只读取挂载状态、访问权限与启动顺序，不试写固件。准备命令与最终安排恢复同样执行检查；取消操作保留独立可用性。
- 系统盘至少预留 512 MiB、启动盘至少 64 MiB。UEFI 恢复盘初步预留按当前根/启动文件系统已分配空间加 2 GiB 估算，另需实际镜像下载、展开与资料暂存空间。估算不保证稀疏文件、后续数据变化或任意磁盘故障下的容量，离线回退仍按实际复制结果检查。
- 后台准备窗口显示真实阶段、阶段已用时间和总用时：检查、暂存、校验、解压/转换、内容检查、资料整理、压缩生成、保存、文件比较及引导准备。没有可计算的总体百分比时不编造百分比；无输出时耗时仍更新。
- 进度通道非阻塞，窗口关闭或显示失败不强制中断后台操作。进度标签只接受固定阶段，不将原始日志、路径或未知标记当作显示内容。镜像 SHA-256 的重复计算合并，校验与来源记录继续保留。

提供源码、八个独立二进制、六个 DEB、两个 RPM 与 SHA256SUMS。测试结果及源码绑定见 [RC.2 验证记录](../validation/v0.5.0-rc.2.md)。[使用指南](../beta-testing.md) · [正式版验收清单](../stable-readiness.md)。

仍为预发布。支持范围仍限定为 ext4 根分区、专用 FAT ESP、标准 GRUB、AMD64/ARM64 UEFI、Secure Boot 已关闭，另有 ext4 恢复盘；自动来源不带桌面，恢复删除全部旧用户与目标个人资料。物理硬件及 Fedora ARM64 完整恢复仍未验收。Mint、ISO 自动部署、Btrfs 目标、LVM/加密/RAID、独立 `/boot` 或 `/home`、共享/OEM ESP 不支持。原生非 UEFI 板卡需单独验证。

## English

This candidate focuses on preparation checks and visible operation progress:

- `check [--storage /mnt/recovery]` aggregates independent results as pass, blocker, unknown or not checked. It covers distribution, root/boot partitions, complete boot/layout rules, required tools, pending reset, Secure Boot, UEFI-variable access, root/boot working space and estimated recovery capacity. A failed check does not hide independent results.
- Missing, unreadable or malformed Secure Boot state is never assumed disabled. UEFI checks read mount/access status and BootOrder without test writes. Preparation and final arming also enforce these checks; cancellation remains independently available.
- Require at least 512 MiB free on root and 64 MiB on boot. Initial UEFI recovery-space reservation estimates allocated root/boot filesystem space plus 2 GiB, excluding actual image download/import/expanded staging. This does not guarantee capacity for sparse files, subsequent data changes or arbitrary disk faults; offline backup still checks actual copy success.
- Background preparation displays real stages, stage elapsed time and total elapsed time, including checks, copying, hashing, decompression/conversion, inspection, normalization, packing, registration, comparison and boot preparation. It uses activity indication without inventing an overall percentage and updates elapsed time during silent work.
- Nonblocking progress prevents a slow/closed window or observer failure from forcibly interrupting the backend. Only fixed stage labels control progress text; raw logs, paths and unknown stage markup do not. Duplicate image SHA-256 work is removed while preserving validation and provenance.

Assets include source, eight executables, six DEBs, two RPMs and SHA256SUMS. See [RC.2 validation](../validation/v0.5.0-rc.2.md), the [testing guide](../beta-testing.md) and [stable-release checklist](../stable-readiness.md).

This remains a prerelease. Scope stays ext4 root, dedicated FAT ESP, standard GRUB, AMD64/ARM64 UEFI, Secure Boot already disabled, and another ext4 recovery volume. Automatic sources have no desktop; reset deletes all old users and target personal files. Physical hardware and full Fedora ARM64 restoration remain unverified. Mint, automatic ISO deployment, Btrfs targets, LVM/encryption/RAID, separate `/boot` or `/home` and shared/OEM ESPs remain unsupported. Native non-UEFI boards require separate validation.
