# Linux Factory Reset v0.5.0-beta.2

## 中文

这是一次状态提示与问题反馈更新：

- 修复恢复资料目录不可访问时，界面可能直接退出的问题；资料缺失、损坏或权限异常时保持恢复操作不可用，并给出提示。
- 新增“导出诊断报告”：普通用户即可保存本地 JSON；终端支持 `linux-factory-reset diagnose` 和 `linux-factory-reset diagnose --output 新文件名.json`。
- 报告只含程序/系统/内核版本、架构、UEFI、文件系统类型、准备状态及工具可用性。排除用户名、主机名、个人路径、磁盘 UUID、镜像网址、原始日志和原始恢复清单；不会自动上传。保存仅创建 `0600` 新文件，拒绝覆盖和符号链接。
- 改善 `status` 在资料不可读时的错误指引，更新中英双语反馈说明。

提供八个独立二进制、六个 DEB、两个 RPM、`SHA256SUMS` 和源码。安装与反馈见 [公测指南](../beta-testing.md)；本次验证和沿用的恢复基线见 [Beta.2 验证记录](../validation/v0.5.0-beta.2.md)。

恢复引擎、离线救援、首次开户和固件写入逻辑未变。本次新增诊断/权限回归测试及发行版安装兼容性检查；完整重启恢复沿用 Beta.1 的验收结果，没有将旧运行标成 Beta.2 新运行。仍属限定范围 Beta：平铺 ext4 根分区、专用 FAT ESP、标准 GRUB、AMD64/ARM64 UEFI、Secure Boot 已关闭，另有 ext4 恢复盘。自动恢复源不带桌面；恢复删除全部旧用户和目标个人文件。物理硬件、Fedora ARM64 完整恢复、Mint、安装 ISO 自动部署、Btrfs 目标、LVM/加密/RAID、独立 `/boot` 或 `/home`、共享 ESP 仍未验收或不支持。

## English

A focused status-handling and feedback update:

- Fix GUI exit when the recovery-metadata directory cannot be accessed. Missing, corrupt or inaccessible metadata keeps recovery actions unavailable and shows guidance.
- Add local diagnostic export for ordinary users through the GUI, `linux-factory-reset diagnose`, or `linux-factory-reset diagnose --output new-report.json`.
- Reports allowlist application/system/kernel versions, architecture, UEFI, filesystem types, preparation status and tool availability. They exclude usernames, hostnames, personal paths, disk UUIDs, image URLs, raw logs and raw recovery metadata. Nothing is uploaded. Export exclusively creates a new `0600` file; existing files and symlinks are refused.
- Improve unreadable-state CLI guidance and bilingual feedback instructions.

Assets: eight standalone executables, six DEBs, two RPMs, `SHA256SUMS` and source. See the [testing guide](../beta-testing.md) and [Beta.2 validation record](../validation/v0.5.0-beta.2.md).

The restoration engine, offline rescue, first-user setup and firmware-writing logic are unchanged. This update adds diagnostic/permission regression tests and distribution install/compatibility checks. Full reboot/restore acceptance is inherited from Beta.1, not presented as a fresh Beta.2 run. Scope remains plain ext4 root, dedicated FAT ESP, standard GRUB, AMD64/ARM64 UEFI, Secure Boot already disabled, and an additional ext4 recovery disk. Automatic sources have no desktop; restoration deletes all old users and target personal files. Physical hardware, full Fedora ARM64 recovery, Mint, automatic installer-ISO deployment, Btrfs targets, LVM/encryption/RAID, separate `/boot` or `/home` and shared ESPs remain unverified or unsupported.
